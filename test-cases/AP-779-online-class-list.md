# AP-779 — Online Class List (Master Panel): Test Cases

Automated coverage of the online class list at `/master/online-class/online-class-list`
(`TeacherOnlineClassView.vue`), which the teacher and coaching-center portals also mount:
rendering, search, sort, pagination, the five row actions and their dialogs, and the
regressions its shared store, routes and query helper expose.

The bug class this targets is **a value the API returns but the list shows wrongly** — a
duration left in seconds, a paginator bound to the wrong fields, a search that matches
markup nobody can see. A test that re-reads whatever the database happens to hold cannot
pin those down, so every UI case here feeds the list a fixed, recorded response and asserts
what that exact response must render as.

**Applies to:** the Apical Vue front-end (`blubird-interactiveltd/apical`).
**Ticket:** [blubird-interactiveltd/apical#779](https://github.com/blubird-interactiveltd/apical/issues/779).
**Specs:** `tests/tickets/AP-779-online-class-list/*.spec.ts` (8 files).
**Test data:** `data/regular/onlineClass/*RegularTestData.json`, `data/edge/onlineClass/*EdgeTestData.json`.
**Fixtures:** `fixtures/api/onlineClassList.response.json` — a recorded `GET /api/v1/online-class` page of 20 classes.

**Global preconditions for every case below:**

- `.env` is populated (`BASE_URL`, `API_URL`, `ORGANIZATION`, `MASTER_EMAIL`, `MASTER_PASSWORD`).
- The Apical front-end at `BASE_URL` is running and talks to `API_URL`.
- The master account can open the online class list.

**Four properties of this suite that are deliberate:**

- **Only the online-class endpoints are stubbed.** `GET /online-class`, `GET /online-class/{id}` and
  `POST /online-class/duplicate` are served by `OnlineClassApiMock`; login, profile, permissions and
  ribbons still reach the real backend with a real token. The list renders inside a genuine session and
  only its data is controlled, so no case depends on what the database holds and none writes to it.
- **The stubbed search answers like the server.** `utils/onlineClassSearch.ts` reproduces
  `OnlineClass::scopeOfSearch` (LIKE on title OR raw-HTML description), so a UI search case asserts
  against the rows the backend would really return. `onlineClassApi.live.spec.ts` checks the backend
  half separately, against real data, when `RUN_LIVE=1`.
- **Known defects are expected failures, not deletions.** Each case that exposes a finding below calls
  `test.fail()` next to the source line that causes it. Fixing the app turns the case red — Playwright
  reports an expected failure that passed as a failure — which is the signal to remove the marker.
- **Chromium only.** The config defines three browser projects; what is verified is data binding and
  request behaviour, which is identical in every engine.

The suite is **not** enrolled in `scripts/e2e-suites.config.sh`, so it does not run in CI yet.
Enrolling it is a separate decision: it needs a reachable environment and a master account in the
repository secrets.

## How the IDs below map to what a run prints

Every test title ends with its case ID, e.g. `shows DURATION(H) in hours, not seconds (AP-779-TC-027)`,
so a failure names its row here directly. Where one documented case holds two independent claims the
spec splits it into an **a**/**b** pair — AP-779-TC-013 (the empty state renders) and AP-779-TC-013b (its
message reads sensibly) are both reported against the TC-013 row. The numbers are the same as the design
document `automation_document/online-class-list/online-class-list-test-cases.html`, prefixed with the ticket.

## Behaviours confirmed by this suite

- The list renders one row per API item, in API order, with the right modules, chapters, tags and featured flag.
- Search sends nothing below three characters, sends `page=1&search=<term>` from the third, and restores the full list when cleared.
- Search results render exactly what the backend's LIKE rules return, including matches on description text.
- HTML in a title or tag is escaped in the table.
- View, duplicate, copy-link, edit and share each call the right endpoint with the right id — including when four rows share a title.
- A duplicate posts `{online_class_id}`, confirms, and reloads the list with the copy at the top; a failed duplicate keeps the dialog open.
- Paging keeps the search term, and a new search resets to page 1.

These are expectations from reading the source; they become confirmed once the suite has run green
against an environment.
